How it works

Three steps.
Zero magic.

It does not guess. It reads your real DOM and gives you the selector that passes.

01 / CAPTURE

Run your suite as usual

You install the reporter. When a locator fails, Healify captures the DOM and metadata. No CI changes.

02 / ANALYSIS

Analyses 100% offline

It walks ARIA roles, text and structure, then ranks by stability. No AI, no cloud.

03 / FIX

Copy and paste

Open healify-report.html. You see before/after and copy the selector that works.

100% Local

Nothing leaves. No API key, no account, no tracking.

12ms

1k+ nodes analysed in milliseconds, with no dependencies.

ARIA-first

Prefers getByRole, visible text and roles. Selectors that survive a refactor.

No AI

Deterministic heuristics. Same input, same output, every time.

HTML report

healify-report.html with a visual diff and a fix you can copy.

MIT

Open source, no vendor lock-in. Yours forever.

Shadow DOM & iframes

It sees inside web components and frames, and tells you which frame to switch to.

Page Objects

If the selector lives in pages/, fix finds it and fixes it there.

Your thresholds

minConfidence, healEnabled and more, via config file or environment variable.
