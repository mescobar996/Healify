# Plan G9 — `healify fix --watch` (modo watch)

**Fecha:** 2026-08-03 · **Gap:** G9 (`docs/research/competitive-gaps.md`) · **Prioridad:** P3

## Problema

Playwright `--ui` re-corre los tests cuando cambia un archivo; Healify no tiene el análogo de
ese loop. El usuario debe correr sus tests, esperar, y volver a ejecutar `healify fix` a mano
cada vez que sale un reporte nuevo. Con tests que se corren en CI/local continuo, el flujo
real es: tests → reporte nuevo → `fix` → tests → reporte nuevo → `fix`...

## Diseño

`healify fix --watch [reporte.json] [flags]` — vigila `healify-report.json` (o el path dado) y
re-aplica `fix` automáticamente cada vez que el archivo cambia de contenido (nueva corrida).

- Mismo juego de flags que `fix` salvo `--pr`/`--interactive` (no tienen sentido en un loop).
- Detección de cambio: `mtimeMs + size` del archivo (stamp). Primera ejecución aplica siempre;
  después solo si el stamp cambió. El reporte borrado y recreado vuelve a aplicar.
- Polling con `setInterval` + `statSync` (cero dependencias, cross-platform). `--interval <ms>`
  para ajustar (default 1000). El loop nunca `process.exit` — `fix` sí lo hace en una pasada.
- El cuerpo de la aplicación (leer run → `appendHistory` → `fix` → `fixAst` → imprimir) se
  extrae a `applyFixOnce(reportPath, opts)` reutilizable, para que una corrida de watch sea
  idéntica a `healify fix` normal (misma semántica de dry-run/force/no-ast/no-pom).
